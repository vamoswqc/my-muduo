# 日志输出总体介绍

本项目日志输出一共涉及4个文件，分别是：

- `Logger.h`：定义日志记录器类 `Logger` 的接口。
- `Logger.cc`：实现日志记录器类 `Logger` 的成员函数。
- `Timestamp.h`：定义时间戳类 `Timestamp` 的接口。
- `Timestamp.cc`：实现时间戳类 `Timestamp` 的成员函数。

1、首先也是最主要的一个类是`Logger`，它负责记录日志信息。它只有一个成员变量`logLevel_`，用于存储当前的日志级别。但是`Logger`类的构造函数是私有的，只能通过`instance()`函数获取到唯一的实例（具体见单例模式的实现）。然后它有两个成员函数：

- `setLogLevel(int level)`：设置日志级别。
- `func_Log(string msg)`：输出日志信息。`

2、对于输出日志信息，首先通过instance()函数获取到唯一的实例，然后根据当前的日志级别（宏函数定义）调用setLogLevel()函数设置日志级别。最后调用func_Log()函数根据级别对应输出并配上**时间戳和具体的日志消息。**

3、对于时间戳，即在Timestamp.h和Timestamp.cc中，Timestamp类就是只有一个int64_t型整数成员变量的类。这个成员变量通过成员函数now()函数获取到当前时间的毫秒级时间戳。然后通过toString()函数将其转换为字符串格式即可输出。\*\*

## 单例模式的实现

```cpp
class Logger : noncopyable{
public:
    static Logger& instance(); // 获取日志实例函数
    void setLogLevel(int level); // 设置日志级别
    void func_Log(string msg); // 输出日志信息函数
private:
    LogLevel logLevel_; // 当前日志级别
    Logger(){}; // 构造，禁止外部创建实例
};
```

`Logger.h`中通过`instance()`函数实现了单例模式。通过调用此函数，程序可以在任何地方获取到同一个 Logger 对象，确保整个应用中只有一个日志记录器实例。对于一个Logger对象，**它的构造函数是私有的，只能通过`instance()`函数（如下）获取到。**

```cpp
Logger & Logger::instance() {
    static Logger logger; // 通过用局部静态变量实现单例模式
    return logger;
}
```

`instance()`函数中定义了一个局部静态变量`logger`，局部变量特点是第一次执行到该语句时才会初始化，并且初始化后会一直存在，直到程序结束，整个程序中只有一个实例。其能保证：
1、线程安全：在 C++11 及以上标准中，局部静态变量的初始化是线程安全的；编译器会自动保证多个线程同时调用 instance() 时，不会创建多个实例

2、懒加载：只有在第一次调用 instance() 时才会创建 Logger 实例，避免了程序启动时的不必要开销
实际中可以通过`Logger &logger=Logger::instance()`这样一条语句使用。下面是具体的工作原理：

1）当第一次调用`instance()`函数时，局部静态变量`logger`会被初始化，返回其引用。
2）后续调用`instance()`函数时，直接返回已初始化的`logger`引用，不会重新初始化。
因此，无论在程序的哪个地方调用`Logger::instance()`，都将得到同一个 Logger 实例，确保了日志记录的一致性和全局访问性。

## 为什么不直接构造而是用单例模式

构造函数的设计目的是创建新对象，而单例模式的核心要求是确保只创建一个实例。如果直接构造函数，那么每个调用者都可以创建一个新实例，并且构造函数没有返回值，无法在已有实例存在时返回该实例。
**而通过将构造函数设为私有，并且构造函数里没有任何代码，这样就保证了不能通过`Logger logger1`这种方式创建实例，而是只能通过`Logger &logger=Logger::instance()`函数获取到实例。**

**对于这条语句，我们发现instance()中才是真正定义了一个`static Logger logger`，由于这个logger是静态变量，全局唯一，因此`instance()`函数也可定义为`static`，这样也能做到直接通过类名调用（如 Logger::instance()），无需先创建对象。**

此后`Logger logger=Logger::instance();`和`Logger logger2=Logger::instance();`中，`logger`和`logger2`指向的是同一个日志记录器实例，确保了日志记录的一致性和全局访问性。

# 利用宏函数输出日志信息

```cpp
#define LOG_INFO(Logmessage,...) \
    do{\
        Logger &logger=Logger::instance();\
        Logger::instance().setLogLevel(Logger::kInfo);\
        char buf[1024]={0};\
        snprintf(buf,1024,Logmessage,##__VA_ARGS__);\
        logger.func_Log(buf);  \
    } while(0)
```

创建原理讲完，接下来看使用的原理。观察到Logger类中还有一个`func_Log`和`setLogLevel`函数，分别是输出日志信息和设置日志级别函数。前者就是正长打印日志信息，后者通过另一个私有变量`logLevel_`来设置日志级别（这个变量是枚举类型，有kDebug、kInfo、kWarn、kError、kFatal五个）。关键是上面这一个宏定义函数：

1、宏参数处理：`Logmessage`：日志消息的一个**字符串**（类似 printf 的格式）
`...`：可变参数，用于填充格式字符串中的占位符
`##__VA_ARGS__`：C99 特性，处理可变参数，当没有可变参数时会自动删除前面的逗号
2、一般使用`do-while(0)`语句，确保宏函数执行一次立即结束。
3、首先获取单一实例后，调用`setLogLevel`函数设置日志级别，其中`Logger::instance()`返回的就是唯一的Logger实例。
4、然后使用`snprintf`函数将格式字符串和可变参数格式化为一个字符串`buf`。
5、最后调用`logger.func_Log(buf)`输出日志信息。

相当于就是一个全局的`printf`函数，只不过用宏函数的方式，比较简洁并且可以方便的通过不同名字直接调用。
这种设计充分利用了 C 语言宏的特性，结合单例模式和格式化输出，提供了一种简洁、高效的日志记录方式。这种设计在 C/C++ 项目中非常常见，特别是在需要大量日志记录的场景下，能够显著提高代码的可读性和维护性。

## 时间戳的设计精髓

在`Logger.cc`中，输出日志信息时会调用`Timestamp::now().toString()`来获取当前时间的字符串表示。这个设计的精髓在于：

一、其构造函数由explicit修饰，因为其是单参数构造函数，explicit修饰后就能禁止隐式类型转换。

二、now()函数被设计成静态成员函数，因为获取当前时间是一个与具体 Timestamp 实例无关的操作。如果不是静态函数，我们就需要先Timestamp t1；然后通过t1.now()来获取当前时间，这样又还得析构t1，这是个浪费。

而通过静态函数，我们可以不创建临时对象，直接调用now()函数返回一个临时对象，表示当前时间。并且now()函数中返回的临时对象可以自动析构，这也就是为什么Timestamp类不用声明析构函数的原因。

注：在 C++11 及以上标准中，对于 Timestamp::now() 返回的临时对象，编译器会优先使用移动构造函数来提高效率，避免了复制构造函数的开销。
