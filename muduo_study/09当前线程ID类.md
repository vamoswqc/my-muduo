# 当前线线程ID类

CurrentThread 是 muduo 网络库中用于高效获取当前线程 ID 的工具类，采用了命名空间的方式组织代码。

## 核心设计思想

1. 线程局部存储（TLS）

```cpp
extern __thread int t_cachedTid;  // 头文件声明
__thread int t_cachedTid=0;       // 源文件定义
```

每个线程都有独立的 t_cachedTid 副本，互不干扰
初始值为 0，表示尚未缓存

2. 懒加载缓存机制

```cpp
inline int tid(){
    if(__builtin_expect(t_cachedTid==0, 0)){
        cacheTid();
    }
    return t_cachedTid;
}
```

首次调用时，t_cachedTid 为 0，触发 cacheTid() 获取真实线程 ID
后续调用直接返回缓存值，避免重复系统调用

3. 分支预测优化

```cpp
__builtin_expect(t_cachedTid==0, 0)
```

\_\_builtin_expect 是 GCC 提供的分支预测提示
第二个参数为 0 表示：编译器认为 t_cachedTid==0 为假的概率更大
优化 CPU 流水线，减少分支预测失败的性能损耗

4. 系统调用获取线程 ID

```cpp
void cacheTid(){
    if(t_cachedTid==0){
        t_cachedTid = static_cast<pid_t>(syscall(SYS_gettid));
    }
}
```

为什么不用 getpid()？

因为getpid() 返回的是进程 ID，多线程环境下所有线程共享同一个进程 ID

1. `syscall(SYS_gettid)`：直接调用 Linux 系统调用获取轻量级进程 ID（即线程 ID）
   Linux 线程模型：Linux 没有真正的线程概念，线程是通过**轻量级进程（LWP, Light Weight Process）**实现的：
   进程A (PID=1000)
   ├── 主线程 (TID=1000) ← TID = PID
   ├── 子线程1 (TID=1001)
   └── 子线程2 (TID=1002)

2. `static_cast<pid_t>`：syscall() 返回 long 类型，需转为进程/线程ID类型

## 设计优势总结

1. 线程安全：\_\_thread 线程局部存储 ——>无需锁，无竞态条件，同时每个线程缓存自己的 TID，避免重复系统调用，线程创建时初始化，线程销毁时自动释放。
2. 高性能：缓存机制 + 分支预测 ——>避免频繁系统调用
3. 延迟初始化：只在需要时获取
4. 简洁接口：命名空间 + 内联函数 ——> CurrentThread::tid() 直接调用

## 使用场景

在muduo 库中，CurrentThread::tid() 广泛用于：
日志系统中标记日志所属线程
线程池管理和调度
线程局部数据的索引和管理
