# noncopyable

noncopyable 是一种设计模式，它通过简单的继承关系，为类添加了不可复制的特性，而不需要在每个类中重复编写删除拷贝构造函数和赋值运算符的代码。具体见`noncopyable.h`。

## 设计精髓

### 1. 防止意外复制

通过将拷贝构造函数和赋值运算符声明为delete，确保派生类不会被无意中复制，从而避免浅拷贝所带来的问题。

### 2. 资源所有权控制

在网络编程中，许多类持有系统资源（如套接字、文件描述符等）。通过禁止复制，明确资源的所有权，避免多个对象同时持有同一资源导致的冲突。

### 3. 多线程安全

在多线程环境中，对象复制可能导致竞态条件和数据不一致问题。禁止复制简化了线程安全的管理。

### 4. 清晰的接口设计

通过继承 noncopyable，设计者明确表达类的语义：这个类不应该被复制。这种设计提高了代码的可读性和意图表达。

## 实现细节

```cpp
class noncopyable {
public:
    noncopyable() = default;
    ~noncopyable() = default;
protected:
    noncopyable(const noncopyable&) = delete;
    noncopyable& operator=(const noncopyable&) = delete;
};
```

### 成员函数说明：

- **默认构造函数和析构函数：** 使用=default使类保持默认构造和析构能力
- **拷贝构造函数：** 被delete声明，防止通过拷贝构造创建新对象
- **赋值运算符：** 被delete声明，防止通过赋值运算符创建新对象

当其子类需要拷贝时，必须先调用基类 noncopyable 的拷贝构造，基类被delete声明，所以拷贝不了自然而然子类也不能拷贝了。
而当声明一个子类时，必须先调用基类的构造函数，由于基类的构造函数是default，所以没任何影响。

### 典型使用类：

- **Eventloop**：事件循环管理
- **TcpConnection**：TCP连接管理
- **Socket**：套接字封装

## 优势

### 减少代码冗余

避免在每个需要禁止复制的类中重复编写相同的代码

### 提高代码一致性

统一处理不可复制类的实现方式

### 增强代码可读性

通过继承 noncopyable，明确表达类的不可复制性

## 设计哲学

这种设计体现了C++编程中的一个重要原则：**明确表达意图**。通过这种惯用法，我们：

- 在编译期就阻止不安全的操作
- 使得类的设计意图在代码层面清晰可见
- 为复杂系统中的资源管理提供基础保障
