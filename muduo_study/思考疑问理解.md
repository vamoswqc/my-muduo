在TcpServer::newConnection()函数中，当接受了一个新用户连接，就要把这个Tcp连接封装成一个TcpConnection对象，也就是上面代码中的new TcpConnection(…)。然后用一个共享型智能指针来管理这个对象。所以为什么这里要把TcpConnection用智能指针来管理啊？

## 在日志输出中，为什么Logger类是一个单例模式而Timestamp类不是单例模式，明明两者都是通过某个成员函数来获取实例的？

对于Logger类，它的实例是全局唯一的，任何地方都需要通过 Logger::instance() 来访问一个日志实例，避免在每个需要日志的地方都创建 Logger 对象，所以需要使用单例模式来管理它的实例。而Timestamp类核心职责是表示特定时间点，需要多个不同的实例来表示不同的时间，多个实例之间互不影响。

对于两者的静态方法：其实本质上都是希望不创建一个实例对象，而是通过静态函数来获取一个实例。只不过Logger::instance()返回的实例也是个静态对象，是全局唯一的，每次调用都返回同一个东西。而Timestamp::now()返回的是一个临时对象，并且每次调用都会创建一个新的临时对象，两者区别在于这里。

因而单例模式不是通过静态函数来获取实例，而是通过构造函数来创建这个唯一的实例。

## 浅谈one loop one thread

顾名思义，一个EventLoop对应一个线程，Eventloop就是一个线程的事件分发器，我们知道在I/O多路复用中，不管采用哪种机制，本身的fd（一个socket连接）以及event（感兴趣事件）、revent（实际发生的事件）等东西都是需要的。而EventLoop（每个线程）其中就有这些东西，也就是其中的channle类来封装的。而其中的另一个核心模块poller类可以理解为epoll，它是一种机制，是一种技术，用来监视这些channle。

这样一来，底层复杂的文件描述符和事件管理抽象成简单的对象，而传统的I/O多路复用机制里面很多的细节就变成了EventLoop中的Poller和Channel来处理，这样代码变简单了，提高了可维护性。

```cpp
EventLoop -> Poller (获取活跃事件)
         -> 遍历活跃Channel
         -> 调用Channel::handleEvent()
         -> 执行具体的回调函数
```
